Transform renders an existing Marmo component as another intrinsic element. It keeps the original class logic and component props, while TypeScript validates the selected element's additional props.

<Alert type="info" heading="Astro: use inline transformation">
Astro supports `$_as` for its supported HTML tags. The `ma.transform()` builder is available only in React and Solid. In Astro, choose the tag while rendering and add consumer classes with `class`; the result is static HTML. SVG, custom tags, and raw-text `script`/`style` elements are outside the Astro adapter's supported tag set.
</Alert>

Features
: works with any Marmo component
: automatically infers the new element's props
: preserves the types and class logic of the original component

## Inline transformation

Pass `$_as` to render a Marmo component as a different intrinsic element. Use it primarily for semantic polymorphism: for example, rendering text as a label or a button-styled component as a link.

:::Choice{id="react"}

```tsx
import ma from "@marmo/react"

const MyButton = ma.button`
  absolute
  min-w-300
`

const MyComponent = () => (
  <>
    <MyButton $_as="a" href="/settings">Settings</MyButton>
    <MyButton>Save</MyButton>
  </>
)
```

:::

:::Choice{id="solidjs"}

```tsx

`

  </>

```

:::

The selected element's props are inferred automatically. Props used by the source Marmo component are preserved, including ordinary custom props and variant props. Additional props are validated against the transformed intrinsic element. If a source prop and an intrinsic prop have the same name, the source component's type takes precedence.

:::Choice{id="react"}

## Builder API

In React and Solid, use the builder API when you want a reusable transformed component, or add more classes with a tagged template. In Astro, use `$_as` at the call site and add classes with `class` instead.

:::Choice{id="react"}

```tsx
import ma from "@marmo/react"

const MyButton = ma.button`
  absolute min-w-300
`

const TransformButton = ma.transform(MyButton).span

const TransformButtonWithClasses = ma.transform(MyButton).span`
  bg-primary
  text-white
`

const MyComponent = () => {
  return (
    <>
      <TransformButton />
      <TransformButtonWithClasses />
    </>
  )
}
```

:::

:::Choice{id="solidjs"}

```tsx
import ma from "@marmo/solid"

const MyButton = ma.button`
  absolute min-w-300

const TransformButton = ma.transform(MyButton).span

`

    </>
  )
}
```

:::

**Result**

```html title=output.html

<span class="absolute min-w-300 bg-primary text-white"></span>
```

### React and Solid v1 limitation: Marmo components only

<Alert type="warning" heading="No support for non-Marmo components yet">
Marmo's `transform` only accepts Marmo components in v1.

```tsx
const SomeComponent = () => <div className="pt-10" />

// ❌ does not work:
const InvalidMarmoComponent = ma.transform(SomeComponent).span``

// Extending first creates a Marmo component, so this is accepted:
const MarmoComponent = ma.extend(SomeComponent)``
const TransformedComponent = ma.transform(MarmoComponent).span
```

This workaround does not preserve arbitrary rendering when transformed. `ma.extend(SomeComponent)` preserves `SomeComponent` while it remains extended, but transforming that Marmo component renders the selected intrinsic element directly. Component internals, hard-coded classes that were not passed through Marmo, and other rendering behavior from `SomeComponent` are not retained. Prefer transforming a component originally created with Marmo.

</Alert>


## Dynamic transformations

The value of `$_as` can be derived from props. React and Solid also support changing it from reactive browser state.

:::Choice{id="react"}

```tsx
import { useState } from "react"
import ma from "@marmo/react"

const Alert = ma.div`rounded-box p-4`

const Example = () => {
  const [inline, setInline] = useState(false)

  return (
    <>
      <button onClick={() => setInline((value) => !value)}>Toggle</button>
      <Alert $_as={inline ? "span" : "div"}>Status</Alert>
    </>
  )
}
```

:::

:::Choice{id="solidjs"}

```tsx
import { createSignal } from "solid-js"
import ma from "@marmo/solid"

const Alert = ma.div`rounded-box p-4`

const Example = () => {
  const [inline, setInline] = createSignal(false)

  return (
    <>
      <button onClick={() => setInline((value) => !value)}>Toggle</button>
      <Alert $_as={inline() ? "span" : "div"}>Status</Alert>
    </>
  )
}
```

:::

:::Choice{id="astro"}

```astro
---
import ma from "@marmo/astro"

interface Props {
  inline?: boolean
}
const { inline = false } = Astro.props
const Notice = ma.div`rounded-box p-4`
---
<Notice $_as={inline ? "span" : "div"}>Status</Notice>
```

:::

<Alert type="info" heading="Astro: tag selection happens during rendering">
The Astro example chooses a tag from build-time props. It does not react to browser state, and Marmo components cannot use `client:*` hydration directives. The DOM replacement and hydration guidance below applies to React and Solid.
</Alert>

Changing `$_as` replaces the underlying DOM element. This can reset refs, focus, text selection, DOM-local state, and nested component state. Prefer keeping the semantic element stable when only its appearance or layout changes:

:::Choice{id="react"}

```jsx
<Alert className={inline ? "inline" : "block"} />
```

:::

:::Choice{id="solidjs"}

```jsx
<Alert class={inline() ? "inline" : "block"} />
```

:::

:::Choice{id="astro"}

```astro
<Notice class={inline ? "inline" : "block"}>Status</Notice>
```

:::

For reusable display choices, use a variant instead:

```tsx
const Alert = ma.div.variants<{ $display: "block" | "inline" }>({
  variants: {
    $display: {
      block: "block",
      inline: "inline",
    },
  },
})
```

### Server rendering and hydration

In React and Solid, dynamic transformations are SSR-safe when the server render and the first client render resolve to the same intrinsic element. A value derived from stable props is safe, but a value read directly from `window.matchMedia`, `localStorage`, or `Math.random()` can cause a hydration mismatch.

Use a deterministic initial value shared by the server and client, then update it after hydration when necessary. Marmo does not suppress or repair hydration mismatches caused by application state.

## Transform variants

:::Choice{id="react"}

```tsx
import ma from "@marmo/react"

const VariantDiv = ma.div.variants<{ $size: "sm" | "md" }>({
  base: "absolute min-w-300",
  variants: {
    $size: {
      sm: "w-10 h-10",
      md: "w-20 h-20",
    },
  },
  defaultVariants: {
    $size: "md",
  },
});

const Main = ma.transform(VariantDiv).main`
  text-neutral
  tracking-wide
`;

const MyComponent = () => {
  return (
    <>
      <Main $size="sm" />
      <Main $size="md" />
    </>
  )
}
```
